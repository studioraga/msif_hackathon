# M5.1 — PyTorch/NumPy locked environment and RTX 5060 Ti qualification

## Source of truth and status

The uploaded **PyTorch dependencies addition for msif** procedure selected
Python 3.12.3, NumPy 2.5.4, torch 2.14.0 cu130, CUDA toolkit 13.3, driver
580.159.03, and an RTX 5060 Ti with compute capability 12.0. It includes
proposed test scripts and local candidate PASS evidence, but acceptance of
the **project `.venv`** is a separate reproducibility gate.

Dependency source: `pyproject.toml`. Lock: `uv.lock`. The GPU group uses an
explicit PyTorch CUDA 13.0 index. The core `requirements.txt` deliberately
does not install torch; use `uv sync --locked --group gpu` for the intended
Blackwell environment. Requires x86_64 Ubuntu Node1; do not apply cu130
lock assumptions to the ARM64 Jetson Node2.

## Stage A — disposable candidate verification

Preserve the uploaded candidate evidence as historical artifacts, not as
a source of true package declarations. Prefer read-only verification of
`/tmp/msif-pytorch-2.14.0-cu130` using
`scripts/validate/pytorch/qualify_pytorch_candidate.sh`. This original
script deletes `/tmp/msif-torch-extensions`; inspect before use.
Pass criteria: CUDA device name and sm_120 capability, torch CUDA 13.0,
allocation, elementwise/matmul correctness, CUDA event timing, repeat with
`CUDA_DISABLE_PTX_JIT=1`, compiled extension for sm_120, cuobjdump ELF
inspection and extension correctness with JIT disabled. Candidate SUCCESS
does not establish locked `.venv` qualification.

## Stage B — generate and validate uv.lock

```bash
uv lock
uv tree --group gpu
uv sync --locked --group gpu
uv run --locked --group gpu python -c 'import numpy, torch; print(numpy.__version__,torch.__version__,torch.version.cuda)'
./scripts/validate/pytorch/qualify_project_environment.sh
```

The lock must be generated by uv's resolver; do not hand-author a fake
`uv.lock`. Commit it only after uv lock succeeds and inspect torch's wheel
source, platform markers, checksum and transitive NVIDIA dependencies.
The locked environment verification fails closed if `.venv` is absent, if
package versions do not match, if CUDA is unavailable, or if native GPU
operations fail. The full extension and `sm_120` binary gate are implemented
in the accompanying Node1 qualification wrapper.

## Stage C — M5.1 model import and RTL

With the locked venv active, run `./scripts/verify.sh`,
`./scripts/verify_m21.sh`, `./scripts/verify_m22.sh`, and
`./scripts/verify_m51.sh`. The tensor import occurs on CPU despite the
separately qualified GPU wheels. Compare model/RTL/manifest hashes, preserve
source tensor provenance, and run generated RTL under Icarus. Do not commit
`build/`, `logs/`, `.venv/`, checkpoint files or secrets.

## Qualification exclusions

Triton presence is **not** proof of qualified Triton native execution.
PyTorch `weights_only=True` reduces unsafe checkpoint deserialization but
checkpoints remain untrusted inputs and should not contain sensitive model
weights without an approved storage policy. M5.1 does not qualify ONNX,
full-model accuracy, PDK PPA or production governance.
